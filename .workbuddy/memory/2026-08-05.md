## 需求文档升级 v2.0 → v2.1（新增 R26：预约二次确认 + 确认函回执）

用户提出新需求：面试官确认时段后弹信息确认表（核对公司名/邮箱/称呼），确认无误后由本人邮箱向面试官发预约确认函。
原始文案：「尊敬的某某先生或某某女士，某某公司已预约几月几号几点的线上面试会议，如我临时有事，将通过（手机号）与您联系，感谢！」

### 四项决策（2026-08-05 用户拍板，全选推荐方案）
1. **确认表定位 = 提交前插二次确认步**：原表单填完 → 弹确认页核对三要素 → 确认后才落库发信。确认页**限时 3 分钟、不预占时段**，最终提交仍走原子锁（被抢返回 `SLOT_TAKEN`）。避免"落库后确认"导致预约成立却无确认函的状态不一致。
2. **收件邮箱 = 固定用注册验证过的邮箱，只读不可编辑**。防止填假地址导致本人邮箱退信、被判垃圾发件人。想换邮箱须用该邮箱注册的账号预约。
3. **手机号 = 明文写入正文**（用户选择）。属主动知情披露，已登记 §8.7 新增第 7 类数据；owner 后台可维护/清空，清空则文案自动降级为「您预留的联系方式」。
4. **称呼 = 结构化「姓氏 + 敬称下拉（先生/女士/老师）」**，替代原自由文本，避免「尊敬的王先生先生」拼接事故；缺失降级为「尊敬的面试官」。

### 关键工程约束（写入文档）
- **发件主体**：`From` / `Reply-To` = 候选人本人邮箱，面试官可直接回信触达本人；与系统验证码邮件共用 SMTP 但模板/业务类型分离
- **投递可靠性**：纳入既有 Outbox + 幂等键（`appointment_id + 事件类型 + 版本号`）+ 指数退避重试 ≤3 次
- **失败不回滚**：发信失败时预约仍有效，记 `CONFIRM_MAIL_FAIL` + 三通道告警候选人 + 后台手动重发
- **联动**：改期成功重发（主题标注时间已更新）；取消成功发取消告知函
- **反滥用**：确认函只发已验证注册邮箱，发信频次并入 §5 限频体系
- **时间渲染**：统一 UTC+8，跨年补年份
