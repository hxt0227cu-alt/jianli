### 用户核心洞察
此前体系解决了"规范之间谁说了算"（baseline 单一规范源、precedence、AGENTS 精确章节读取）。
但缺"规范/代码/运行之间谁说了算"：即"这条事实属于文档真相还是代码真相？下游文档基于哪个上游版本？代码基于哪个规范版本？"
靠"大模型认真 + Grep"治不了，必须改治理模型：每种事实只有一个 Owner。

### 四类真相源（固化进 AGENTS §9）

- 线上**现在**怎么工作 → deployed commit + runtime config + logs/metrics（运行真相）
- 项目做到哪一步 → baseline + PROJECT_STATE + TASK（项目状态真相）
- 硬规则：**禁止用 PRD/SRS 推断"当前代码已实现什么"**；Review/Audit Mode 先 checkout verified commit 读代码，再比对 approved specs，输出三栏（规范要求/实际实现/差异·技术债）。
