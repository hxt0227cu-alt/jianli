## 1. 服务器初始化

```bash
# 以 root 或 sudo 用户登录服务器后
sudo apt update && sudo apt upgrade -y
# 安装 Docker + Compose v2
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 重新登录生效
docker --version && docker compose version
```

## 2. 上传代码 + 配置环境

```bash
# 本地构建前端（在你的电脑上）
cd /mnt/c/Users/hxt02/Desktop/jianli
npm run build                    # 产出 dist/，与代码一起上传

# 上传到服务器（任选：git clone / scp / 宝塔面板）
# 以 git 为例：
git clone <your-repo-url> jianli && cd jianli

# 创建生产环境变量文件（服务器上执行，密钥只在这里）
cp apps/api/.env.prod.example .env
nano .env                        # 填入全部真实密钥（见第 0 节 P1）
chmod 600 .env                   # 权限收紧，防误读
```

> ⚠️ `.env` 在服务器上，**不要**提交进 git（根目录 `.gitignore` 已含 `.env`？若无则补）。

## 4.5 初始化 owner_admin 账号（管理员登录，必须）

> 生产库没有任何 owner_admin 账号可登录（开发 seed 的密码是占位符，**不可登录**）。
> 用 `scripts/create-owner.sh` 创建/重置管理员账号——密码**只走环境变量**，不写进 `.env` 或任何文件。

```bash
# 在服务器项目根目录执行（先替换邮箱与强密码；密码 ≥10 字符）
JIANLI_OWNER_EMAIL=你的管理员邮箱@example.com \
JIANLI_OWNER_PASSWORD='你的强密码' \
./scripts/create-owner.sh
# 期望输出：[OK] owner_admin 就绪：…（role=owner_admin, verified=true）
```

- 幂等：重复执行同一邮箱会**重置密码**（忘记密码时重跑一次即可）
- 之后用该邮箱+密码登录站点「知识库管理」入口（admin 页面）
- 部署验证清单第 6 节含对应检查项

## 5. 域名 + HTTPS

```bash
# 确认 DNS 已解析到服务器后（第 0 节 P4）：
# ① 把 deploy/nginx.conf 与 .env 中的 <your-domain> 替换为真实域名
sed -i 's/<your-domain>/你的域名/g' deploy/nginx.conf
# ② 申请 Let's Encrypt 证书
./deploy/certbot-init.sh 你的域名 your-email@example.com
# ③ 重启 nginx 生效
docker compose -f docker-compose.prod.yml exec nginx nginx -s reload
```

验证：
```bash
curl -I https://你的域名        # 期望 200 + TLS
curl -I http://你的域名          # 期望 301 → https
```

## 7. 运维

| 操作 | 命令 |
|------|------|
| 看状态 | `docker compose -f docker-compose.prod.yml ps` |
| 看日志 | `docker compose -f docker-compose.prod.yml logs -f api worker` |
| 重启全部 | `docker compose -f docker-compose.prod.yml restart` |
| 更新部署 | 拉代码 → `npm run build` → `./scripts/deploy.sh`（重建镜像）|
| 手动备份 | `./scripts/backup.sh`（PG 逻辑备份 + 知识库卷，默认保留 14 天）|
| 自动备份 | 装 cron：`crontab -e` 加一行（每天凌晨 3 点）`0 3 * * * cd <项目根> && ./scripts/backup.sh >> backups/backup.log 2>&1`；cron 找不到 docker 时行首加 `PATH=/usr/bin:/usr/local/bin` |
| OSS 异地备份（可选） | 装 `ossutil`（阿里云 OSS 客户端）+ 配置凭证后，`OSS_BUCKET=oss://<bucket>/<prefix> ./scripts/backup.sh` 每次自动上传 |
| 管理员账号 | 创建/重置：`JIANLI_OWNER_EMAIL=... JIANLI_OWNER_PASSWORD='...' ./scripts/create-owner.sh` |
| 证书续期 | certbot 已自动续期（compose 未含 cron 时手动每月跑 `certbot-init.sh`）|

## 9. 已知限制与风险

- **备案周期**：内地地域服务器需 ICP 备案（1-2 周），期间域名不可正式对外；可先用 IP:端口验证功能
- **2C4G 容量**：同机 5 容器可跑，但 RAG 问答 + LLM 流式 + 预约并发高时可能吃紧；观测到 CPU 持续 >70% 再考虑升配
- **知识库对象存储**：挂载 `jianli_knowledge` 卷；换机器需迁移该卷（`backup.sh` 已覆盖该卷备份）
- **备份策略**：`backup.sh` 提供 cron 自动备份（PG 逻辑 + 知识库卷，保留 14 天）；**异地备份仍为待办**——建议上线稳定后配置 OSS（见第 7 节），否则服务器磁盘故障仍会丢数据
- **admin 可用时段 UI 缺失**：后端 `availability-overrides` API 完整（设置不可用/强制可用、预约校验联动、变更重算槽位、审计），但 admin 前端尚无「时段设置」入口——需要时先走 API 或等前端补齐
