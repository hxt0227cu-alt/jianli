# UI 线框 v1.0.2 — 个人 AI 问答网站（含作品集 + 数字分身 + 面试预约）

> **文档状态**：v1.0.2 · `status = approved`（用户于 2026-08-27 批准 TASK-CR-AGENT-LAB-001；U2 增加 Agent Lab 场景入口与脱敏执行轨迹）。依据已批准 SRS v1.8 与领域模型 v1.1.8。

> 本文为**低保真文本线框**（wireframe），非视觉高保真稿。定义布局结构、核心组件、关键交互态与异常态；不规定具体 hex 配色 / 字体 / 间距数值。
> 行为依据：`docs/requirements/SRS.md` v1.8（approved，行为唯一源）。页面—用例—需求映射见 §3 与 SRS §10 追踪矩阵。
> 阶段定位：阶段 1 设计工件；后续由架构/ADR、安全设计、OpenAPI/SSE、测试计划依次推进，`baseline.yml development_gate` 全绿后开放功能编码。

## 1. 全局设计规范

### 1.1 设备与语言
- **桌面端优先**（验收基准 ≥1280×720）；移动端仅保证可读，不保证完整交互。
- **纯中文界面**（R6）。
- 风格：简洁清爽，浅色为主；页面 2 项目卡片可含轻量 HTML 动效。

### 1.2 语义色（与 SRS §6.2 状态模型一致，不定义 hex）
| 语义 | 线框表示 | 后端状态 | 含义 |
|---|---|---|---|
| 绿 | `[绿]` | `available` | 空闲可约 |
| 黄 | `[黄]` | （前端 Session 临时态，**不落库、不预占**） | 选中待确认 |
| 红 | `[红]` | `booked` / `owner_locked` / `unavailable` | 已预约/不可约 |
| 灰 | `[灰]` | — | 今天之前 / 置灰不可选 |

> 黄格仅前端临时态：刷新或超时即消失，不参与并发判断（PRD §4.5 黄格澄清）。

### 1.3 顶部全局栏（除登录/注册/找回外所有页面）
```
┌──────────────────────────────────────────────────────────────┐
│ [Logo] 用户的简历问答站        [问答] [项目] [面试表] [登录/头像] │
└──────────────────────────────────────────────────────────────┘
```
- 已登录面试官：右上角显示头像 + 下拉（历史会话 / 退出）；进入面试表无需再次登录。
- admin 入口独立域名/路径，与面试官账号隔离（§8.4 R9）。

### 1.4 异常/反馈统一组件
- 行内错误：字段下方红字 + 图标。
- 全局 Toast：右上角浮层（成功绿 / 失败红 / 警告黄）。
- 限频提示：表单底部黄条"操作过于频繁，请 X 分钟后再试"。

## 3. 核心用户页面线框（U1–U12）

### U1 首页 / 简历问答页（UC-01）
```
┌──────────────────────────────────────────────────────────────┐
│ [全局栏]                                                        │
├───────────────────────────────┬──────────────────────────────┤
│ 简历（拆块）                    │ 问答窗口（§3.2）                │
│ ┌─────────────────────────┐   │ ┌──────────────────────────┐ │
│ │ [头像] 姓名 / 一句话简介  │   │ │ AI：你好，我是用户的数字分身 │ │
│ │ ─────────────────────── │   │ │    想了解我的哪段经历？   │ │
│ │ 教育背景                 │   │ │ ──────────────────────── │ │
│ │ 工作经历                 │   │ │ 用户：...                 │ │
│ │ 技能                     │   │ │                          │ │
│ │ 项目亮点                 │   │ │ [输入框................] │ │
│ │ （文字可复制 R25）        │   │ │ [发送]                   │ │
│ └─────────────────────────┘   │ └──────────────────────────┘ │
│ [⬇ 下载简历 PDF]  [📅 预约面试] │ 推荐问题（读缓存，缺失走兜底） │
│                               │ [Q1] [Q2] [Q3]  （一键提问）   │
└───────────────────────────────┴──────────────────────────────┘
```
- 左栏正文文字可复制（R25）；下载按钮失败提示重试。
- 越界问题：AI 以本人口吻拒答并引导（UC-04）。
- 模型不可用：问答窗显示"服务暂不可用"，不编造（MODEL_UNAVAILABLE）。

### U2 项目展示页（UC-02）
```
┌──────────────────────────────────────────────────────────────┐
│ [全局栏]                                                        │
├───────────────────────────────┬──────────────────────────────┤
│ 项目卡片（HTML 动效）           │ 问答窗口（同 U1，可问项目）     │
│ ┌────────┐ ┌────────┐         │ （结构同 U1 右栏）              │
```

- 场景按钮直接发送预置问题到同一真实问答流；预约场景不绕过登录与 RBAC。
- Trace 显示阶段、状态、白名单工具名、耗时和脱敏摘要；历史消息无 Trace 时不显示空壳。

```

├──────────────────────────────────────────────────────────────┤

│ ┌─────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┐ │
│ │时间 │ 周一   │ 周二   │ 周三   │ 周四   │ 周五   │ 周六   │ 周日   │ │
│ ├─────┼────────┼────────┼────────┼────────┼────────┼────────┼────────┤ │
│ │9:30 │ [绿]  │ [绿]  │ [绿]  │ [绿]  │ [绿]  │ [红]  │ [红]  │ │
│ │10:00│ [绿]  │ [绿]  │ [黄]  │ [绿]  │ [绿]  │ [红]  │ [红]  │ │

│ └─────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┘ │
```

- 网格：每个自然周 7 列 × 25 行（30 分钟，9:30–22:00），页面连续展示从明天起的 15 日窗口并充分使用主内容宽度；日历、日期、时段和摘要正文不使用低于 12px 的关键文字。
- 最晚可约起始 20:30；最短提前量 = 面试日期前一自然日 22:00（UTC+8）。
- SSE 不可用 → 轮询降级。

```
│ 列表：事件│类型(确认函/提醒/告知函)│通道│状态(failed/retry_scheduled/dead_letter)│
│ 退信行：bounced_at / bounce_reason（邮件通道，存 channel_metadata，不属 DeliveryStatus 枚举）│
│ 告警：退信触发飞书候选人告警 + 后台高优先级告警（状态栏标红/高亮）│
│ [手动重发]（同账号每10分钟≤5、每小时≤20，超限提示限频）         │
│   → 新建 NotificationDelivery 尝试（attempt_no+1，幂等键含新 event_version，version+1）│
│ 双通道独立重试不互为兜底；均失败持续高优先级告警                │
└──────────────────────────────────────────────────────────────┘
```

## 5. 关键交互流（时序线框）

### 5.1 预约创建原子流（§3.5 → §3.8）
```
面试表点[绿] → 前端[黄]临时占1.5h（不落库）
  → 弹 U7 表单（填公司/平台/会议号/HR/备注）
  → [下一步] → U8 二次确认（限时3分钟，邮箱只读）
  → [确认提交] → 服务端校验"一家公司一时段"（R12，并集拦截）
     ├─ 被抢占 → SLOT_TAKEN（另一人绿转红）
     ├─ 重复   → DUP_COMPANY / DUP_ACCOUNT（UC-09）
     └─ 通过   → 原子锁写入 + 加密 + 3格转[红] + SSE刷新
              → 双通道提醒(飞书+邮箱) + 飞书同步 + 确认函投递(U9)
              → 通知失败独立重试不回滚预约（CONFIRM_MAIL_FAIL 可手动重发）
```

### 5.2 改期原子事务流（§3.6）
```
U10 [改时间] → 锁新段 → 占新段 → 释旧段 → 提交（同一事务）
  ├─ 新段被占 → SLOT_TAKEN，原预约不变（禁止先释旧格再重选）
  └─ 成功     → 双通道通知 + 飞书同步 + 改期重发确认函（标注时间已更新）
U10 [改会议号] → 原地改字段（不涉及时段占用）
U10 [取消]     → 事务释放3格 + 取消告知函（必须）+ 飞书同步
```

### 5.3 owner 强制取消（§3.7，UC-20）
```
A7/A4 [锁定已约时段] → 输入取消原因 → 原子取消
  → 释放3格变 owner_locked[红] + SSE刷新 + 发取消告知函(主题「已取消」) + AuditLog
  → 后台不提供直接修改/删除预约入口
```
