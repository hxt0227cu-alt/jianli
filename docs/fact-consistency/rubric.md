# 简历事实一致率 · 评定 rubric

> 配合 `fact-bank.md`（26 题期望事实）与 `measure_fact_consistency.py`（产出 Q+A 转录）。
> 本 rubric 定义「一致率」如何算，是页面二 04「94% 事实一致率」SLO 的可复跑度量方法。

## 1. 流程
1. 跑测量脚本，得到 26 题的「问题 + 系统回答全文 + offtopic/grounded 标记」JSON。
2. 逐题对照 `fact-bank.md` 的「期望事实」与「判定要点」。
3. 给每题打一个等级（见 §2）。
4. 按 §3 公式算一致率。

## 2. 等级定义

| 等级 | 含义 | 算入一致率？ |
|------|------|--------------|
| ✅ 一致 | 回答与事实源对齐，无冲突、无无依据编造；允许合理复述/换表述 | 是 |
| ⚠️ 部分一致 | 命中主体但遗漏次要事实，**未引入冲突或编造**；或仅答出期望事实子集 | 是（宽松口径）；否（严格口径，见 §3 注） |
| ❌ 不一致 | 与事实源**冲突**（如把 15 张表说成 11、把拒答率 100% 说成 0%、编造未提及的经历） | 否 |
| 🚫 误拒 | 问题明明在域内（chunk 有答案），系统却 `offtopic=true` 拒答 | 否 |

**关键边界**：
- 「遗漏」≠「冲突」。只答出部分事实但未说错 → ⚠️，不是 ❌。
- 「无依据扩充」：若回答引入事实源**完全没有**的信息且具断言性（如凭空说"我用过 Kubernetes 集群"）→ ❌（等同于编造）。
- 「拒答但应答」：域内问题被拒 → 🚫，单独计数，提示检索/阈值问题。

## 3. 一致率公式

```
一致率(严格) = ✅ 数 ÷ 26
一致率(宽松) = (✅ + ⚠️) 数 ÷ 26
```

- **报告时两个都给**，主指标用**严格**口径。
- **SLO 目标 ≥ 94%**：26 题下，严格口径要求 ✅ ≥ 25（即最多 1 题 ❌/🚫）。
- 若 ⚠️ 较多但严格 ✅ 不足 25，结论写「严格未达标，宽松达标」，不得只报宽松掩盖缺陷。

## 4. 输出样例（填入交付证据）

```
FQ-01 ✅   后端与平台方向（对齐 R0）
FQ-02 ✅   高并发/数据建模/开发者体验（对齐 R0）
...
FQ-26 ✅   greeting 'hi'⊂'litchi' 坑（对齐 J7）
-------------------------------------------
严格一致率 = 26/26 = 100%   （≥94% ✅）
宽松一致率 = 26/26 = 100%
🚫 误拒 = 0
```

## 5. 防作弊约定
- **事实源唯一**：以 `content.py` chunk 文本为准，不凭印象改期望值。
- **改期望值须走变更**：若发现期望事实本身写错，先改 `fact-bank.md` 并注明原因，再重测；禁止为凑分反向删题或放宽判定。
- **脚本只读不改系统**：`measure_fact_consistency.py` 只发请求、落盘转录，不修改任何仓库/运行态。

## 6. 运行命令（WSL，uvicorn 已在跑）

```bash
# 默认跑全 26 题，结果落盘 scripts/fact_consistency_results.json
python3 scripts/measure_fact_consistency.py

# 只跑某几题（题号，逗号分隔）
python3 scripts/measure_fact_consistency.py --only 11,12,17,18
```

跑完把 `fact_consistency_results.json` 的每题 `answer` 文本对照 `fact-bank.md` 打分即可。
