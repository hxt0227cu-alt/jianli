## A. Litchi 毕设深挖（架构细节 + 选型 + 数据 + 评测）

> 现有语料已有：四阶段受控 Agent（Planner/Guard/Executor/Synthesizer）、Milvus+Neo4j、SSE/Checkpoint/Prometheus、业务闭环（病害识别→证据检索→方案推荐→人工审核→门店履约→效果反馈）、90.4 优秀毕设。下面只问缺失的深度。

**A1. 规模与分工**
- 这个毕设是几个人做的？你负责哪些模块，队友（如果有）负责什么？
- 周期多长（从开题到答辩）？代码量、表数、接口数大概多少？

**A2. 为什么是 RAG，不是微调 / 传统检索？**
- 选 RAG 而不是微调大模型，核心 trade-off 是什么？（成本？语料更新？可解释性？）
- 传统 BM25/向量检索解决不了什么问题，才需要 Agent 化？

**A3. 语料从哪来、多大、怎么建评测集？**
- 荔枝领域语料（病虫害/农事）从哪收集？多少条/多少文档？
- 评测集（回答 90.4 分的那套）是怎么构建的？多少条？人工标注还是自动？

**A4. 四阶段 Agent 管线的设计动机**
- 为什么拆 Planner/Guard/Executor/Synthesizer 四段，而不是一个模型一次生成？
- Guard 守卫的规则/白名单具体怎么定义？步骤预算、RBAC、HITL 人工审批各拦什么？
- 如果少一段（比如去掉 Synthesizer），会发生什么？

**A5. Milvus + Neo4j 的选型**
- 向量检索为什么用 Milvus（对比 pgvector / ES）？图查询为什么用 Neo4j？
- 文档证据走 Milvus、病虫害关系走 Neo4j——两者怎么融合进最终答案？
- 注意：泰益智项目你用的是 pgvector（不用 Milvus），毕设却用 Milvus——面试官很可能会追问两者取舍，提前想好怎么答。

**A6. 效果与答辩**
- 90.4 分是怎么评的（答辩评分构成）？答辩现场被评委追问最狠的问题是哪个？
- 有没有真实用户（农户/门店/农技员）用过？有没有准确率/满意度数据？若没有，如实标注。

**A7. 最大的坑 / 如果重来**
- 开发中最难解决的一个问题是什么（具体到技术细节）？
- 如果现在重做这个毕设，最想改哪个设计决策？

> 现有语料已有：5 微服务+9 层 AI 能力矩阵、LangGraph 双协调器（local/Temporal）、5 类业务 Agent、自研 RAG（pgvector 租户隔离）、安全护栏（白名单+HITL+输出审查+四维预算熔断）、EMQX→Kafka→Flink→ClickHouse→dbt、NestJS 115 REST/35 表/2.3 万行 TS、Taro 15 页、ESP32-S3、K8s/Terraform/Helm/GitOps、84 例评测/工具选择 100%/审批绕过 0%、10 例注入 0 越权写、4 例隐私 0 泄露、67/84 漂移证据、流式零丢失零重复（两 Worker 重平衡 18720 事件 lag 0 / 恢复 median 12.6s）、dbt 56289→56218。下面只问缺失的。

**B2. 双协调器的诚实边界（面试官必追）**

**B3. 84 例评测与 67/84 漂移**

**B4. 安全评测细节**

**B5. 流式数据平台**

**B6. 多租户隔离 2/2**
- 租户隔离测了什么（同库不同租户查不到对方数据？）？2 个用例分别是什么？

**B7. 嵌入式边界**

**B8. 最难的 bug / 最有成就感的时刻 / 如果重来**
