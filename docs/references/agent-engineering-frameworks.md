# A. 原文章框架摘要（客观转述，不含本项目映射）

> 本部分**只复述外部文章提出的框架本身**，不做任何"本项目要做什么"的推论。任何"我们要不要做"的判断一律在 B 部分给出。

## A.1 参考 1：AI Infra 九层纵向 + 四横切

**纵向 9 层**

| 层 | 原文定义的职责 | 原文常见技术举例 |
|----|----------------|------------------|
| L0 基础资源 | 算力、存储、网络、密钥与租户隔离 | 云主机 / K8s / 对象存储 / Secret Manager |
| L1 模型与推理 | 模型接入、路由、缓存、Token 预算 | 托管 API / vLLM / LiteLLM / Portkey |
| L2 数据与知识（RAG） | 解析 → 切块 → 向量化 → 检索 → 重排 → 注入 | Embedding 模型 / pgvector / Qdrant / Milvus |
| L3 Prompt 与上下文 | Prompt 版本化、上下文拼装与压缩 | PromptOps（Prompt 即代码） |
| L4 编排与 Agent | 任务规划、状态机、循环 / 分支 / Checkpoint | LangGraph / Temporal / 自研状态机 |
| L5 工具执行 | 工具标准化、权限、沙箱、资源限制 | MCP / API Connector / 代码沙箱 |
| L6 状态与记忆 | 工作 / 短期 / 长期 / 情景 / 语义记忆，TTL 与脱敏 | DB + 向量库 / Mem0 / Zep |
| L7 评测与质量 | 离线 + 在线 + 人审，发布门禁 | RAGAS / DeepEval |
| L8 可观测 | Tracing / Metrics / Logs 全链路 | LangFuse / OpenTelemetry |

**横向 4 能力（贯穿所有层）**：① 安全治理（鉴权、隔离、PII/DLP、注入防护、审批与限频、审计）；② CI/CD 与发布治理（代码 / Prompt / 索引 / 工具 Schema 全部版本化，灰度与回滚）；③ FinOps（Token、存储、Embedding、GPU 计量与成本归因）；④ 开发者体验（Playground、Trace 回放、Eval 看板、SDK/CLI）。

## A.2 参考 2：Agent 落地十二大工程

**纵向能力主链（6 项）**：Prompt 提示词工程 → Context 上下文工程 → Skill 技能工程 → Agent 智能体工程 → Harness 驾驭 / 编排工程 → Loop 闭环工程。原文主张：只做模型选型 + Prompt 调优，最多得到"看起来聪明"的 Demo；从「会回答」到「会行动 / 会上线 / 会进化」需逐项补齐。

**横切支撑体系（6 项）**：Data 数据工程、Ontology 本体工程、Process 流程工程、Evaluation 评估工程、Safety/Governance 安全与治理、Product/UX 产品与体验。原文主张：Agent 会调工具 ≠ 会走业务闭环，Process 与 Governance 是 Demo 与生产级的分界线。

**两套框架的对照（原文视角）**：九层回答"系统由哪些技术栈组成"，十二大工程回答"每样东西怎么做成生产级"，互为透镜、互不替代。

## A.3 原文的三阶段路线图

| 阶段 | 原文描述 |
|------|----------|
| 验证期 | 托管 API + 轻量向量库 + 简单 RAG Chain + 日志 |
| 原型期 | 模型网关 + 专用向量库 + 编排框架 + 多工具 + 评测与 Tracing + 限频 |
| 生产期 | K8s GPU 弹性 + vLLM + 向量库集群 + 工作流引擎 + 记忆中间件 + OpenTelemetry + 发布门禁 + 四横切全落地 |

## A.4 原文的 Harness 执行链（通用形态）

原文把一次 Agent 执行拆为约 15 步：接收请求 → 识别意图 → 判断权限 → 检索上下文 → 识别业务对象 → 识别流程节点 → 匹配 Skill → 选择 Agent → 调用 Skill → 调用工具 → 生成结果 → 安全审核 → 推动流程流转 → 返回用户 → 记录日志；失败则重试 / 降级 / 熔断或人工接管。同时提出「模型路由」按任务类型、风险等级、上下文长度、延迟、成本、合规综合选模型。

> 以上 A.1–A.4 为**原文框架**。原文默认 Agent 可直接调用写操作工具；本项目**不采用该默认**，理由见 B.2。

# B. 本项目适用性矩阵

## B.0 判定口径

| 判定 | 含义 |
|------|------|
| **采用** | 列入 MVP，须在 SRS / 架构 / 测试计划中有对应条目 |
| **简化** | 保留能力目标，但以最低成本实现（不引专用中间件） |
| **延后** | 承认价值，但 MVP 明确不做；对应 `baseline.yml` `deferred`，**不得预建表 / 字段 / 接口 / 空壳类** |
| **不适用** | 与本项目定位或硬规则冲突，**任何阶段都不引入**（除非走 Change Request 改需求） |

> 项目定位：单人、单站点、面试期 1–2 月、低频访问的个人作品集站点。任何"企业级规模"能力默认不成立。

## B.1 十二大工程 + 九层 → 适用性判定

| 框架条目 | 判定 | 本项目做法（MVP 边界） | 依据 / 约束 |
|----------|------|------------------------|-------------|
| **Prompt 提示词工程**（L3） | **采用** | persona card（L1 人格提示词）+ RAG 注入模板 + 越界拒答护栏；Prompt 随代码 Git 版本化 | PRD 人格层 L1；L2 微调见 `deferred: l2_lora` |
| **Data 数据工程 + RAG**（L2） | **采用** | 简历/项目文档 → 解析 → 切块 → Embedding → 检索 → 注入；知识库热更新触发重建索引 | 领域模型 `KnowledgeDocument` / `KnowledgeIndexVersion` |
| **Context 上下文工程**（L3/L6 部分） | **采用（限定）** | 上下文 = 人格 System + RAG 片段 + 有限轮对话历史；**仅工作记忆 + 会话持久化**，不做用户画像与长期记忆推断 | 领域模型 `Conversation` / `Message` |
| **Process 流程工程** | **采用** | 预约端到端流程由**确定性 UI + 后端接口**实现：选时段 → 填表 → 提交 → 通知 → 同步 → 改 / 取消；含并发抢占、公司去重、例外放行 | 用例 UC-08~UC-23；领域模型 §5 状态机 |
| **Evaluation 评估工程**（L7） | **采用（最小集）** | 最小离线评测集（范围内 / 越界各若干）+ 人工抽检；上线前跑一次，不建自动门禁流水线 | 测试计划阶段细化 |
| **Safety/Governance 安全与治理**（横切①） | **采用** | 角色权限隔离、Prompt Injection 护栏、逐列 AES-256-GCM 加密、公司名 HMAC 指纹、限频、审计日志 | 领域模型 §1 存储策略；安全设计阶段展开 |
| **Product/UX 产品与体验**（横切④部分） | **采用** | 三页结构、动态面试表（SSE 实时刷新）、推荐问题（异步缓存 + 兜底）、公告 | PRD R1–R14；不做 Playground / Eval 看板 |
| **Ontology 本体工程** | **采用（已完成形态）** | 由《领域模型 v1.1.2》承担；不额外引入本体工具或语义层 | `docs/design/domain-model.md` |
| **L8 可观测 / Tracing**（横切） | **简化** | 结构化日志 + 关键指标（Token、延迟、错误率）落库或落文件；**不部署 LangFuse / OpenTelemetry** | 单人低频，链路追踪收益低于运维成本 |
| **FinOps**（横切③） | **简化** | 只记录 Token 消耗与月度 API 账单；不做成本归因、不做配额中台 | 无多租户、无成本分摊对象 |
| **CI/CD 与发布治理**（横切②） | **简化** | Git + 基础 CI（lint / test / 迁移 up-down）；**不做灰度、不做 Prompt 灰度回滚平台** | 单实例部署，回滚 = 重新部署上一版本 |
| **L1 模型与推理** | **简化** | 直连 DeepSeek 托管 API 单模型；不引模型网关 | 混元 Fallback 见 `deferred: hunyuan_fallback` |
| **L6 状态与记忆（长期 / 情景 / 语义记忆中间件）** | **延后** | MVP 只有会话级消息持久化；**不引入 Mem0 / Zep**，不建用户画像表 | `deferred`；不得预建字段 |
| **L4 编排与 Agent 智能体工程** | **延后** | MVP **没有 Agent 编排层**：大模型只做 RAG 问答直出；不做意图路由、不做多步规划、不做状态机编排 | PRD 决策#14；`deferred: agent_auto_booking` |
| **Harness 驾驭 / 编排工程** | **延后** | 不建"运行中心"：无 Skill 注册表、无工具路由、无统一降级熔断层；失败处理由各业务模块自行实现（通知重试见领域模型 §5） | 无 Agent 即无需 Harness |
| **Skill 技能工程 / MCP 工具协议** | **延后** | 后端能力以**普通内部服务函数与 REST 接口**提供，**不封装为可被模型调用的 Skill/Tool**，不引入 MCP | `deferred: complex_agent_infra` |
| **多模型路由** | **延后** | 单模型直连，不做按风险 / 成本 / 长度的路由决策 | 见 C.1 |
| **实时问题生成** | **延后** | 推荐问题走后台异步生成 + 缓存 + 固定兜底，页面只读 | `deferred: realtime_question_gen`；PRD R4 |
| **K8s / GPU 集群 / vLLM 自托管** | **不适用** | 单台轻量云主机部署，不引入编排与自托管推理 | 量化否决依据见 C.2 |
| **代码沙箱 / 任意代码执行** | **不适用** | 本项目无"让模型写并执行代码"的场景 | 攻击面远大于收益 |
| **多 Agent 协作 / A2A** | **不适用** | 单一问答职责，不存在多角色协作需求 | 过度设计（AGENTS.md §3） |
| **Agent 自动预约（模型直接写业务数据）** | **不适用（硬禁止）** | 见 B.2 | PRD 决策#14；`mvp_hard_rules` |

## B.2 明确排除：Agent 不得写业务数据（硬规则）

原文 A.4 的执行链默认「⑨ 调用 Skill 算可选时段 → ⑩ 调用工具写面试表」。**本项目明确不采用该路径**，全文不存在"MVP 使用预约 Agent 写面试表"的映射：

- 大模型**只负责问答**（RAG + 人格层 L1），输出纯文本，**不持有任何写操作工具**；
- 预约的创建 / 修改 / 取消，一律经**确定性前端表单 + 后端接口 + 数据库约束**完成，走 UC-08~UC-22 的确定性流程；
- 通知（邮件 / 飞书）由后端事件驱动，不由模型触发；
- 面试表页面为**只读视图 + SSE 推送**，模型无写入通道。

理由：预约涉及真实人际承诺与外发通知，误触发不可回滚；确定性流程可被数据库唯一索引与行锁**证明**正确，模型调用链无法给出同等保证。此项为 `docs/baseline.yml` `mvp_hard_rules` 条目，**违反即停止并报告**。

# C. 已形成的 ADR 候选输入（推理方案）

> 本部分是**待架构阶段确认的决策输入**，不是已接受的 ADR。正式结论以 `docs/adr/ADR-00x`（status=accepted）为准。

## C.1 生产用托管 API，自托管仅作实验环境

| 环境 | 用途 | 模型层 | 计费 | 状态 |
|------|------|--------|------|------|
| **生产（MVP）** | 对外站点 | DeepSeek 托管 API（单模型）；混元 Fallback 为规划冗余、**延后** | 按 Token，无提问不计费 | 已确认（MVP 单 DS） |
| **实验** | 作品集验证，非对外 | 按量租 GPU 部署 7B/14B 蒸馏模型 | 按小时，实验结束立即释放 | **延后**（MVP 后可选） |

自建边界：**自建并云端部署网站、RAG、知识库、人格编排、业务与数据服务；大语言模型经第三方托管 API 调用**。基础模型是可替换组件，不影响"自建 AI 应用"的定性。

## C.2 否决「自托管完整 DeepSeek」的量化依据

- **完整版不可行**：DeepSeek-V3 为 671B 总参数 MoE，官方推理示例即为双节点 × 每节点 8 进程的多机多卡部署，非单卡个人项目可承载；
- **蒸馏版能跑 ≠ 效果够用**：R1-Distill-Qwen-7B 权重约 15.2GB，但权重体积 ≠ 显存需求（KV Cache、运行时与并发开销显著抬高占用）；量化降显存但牺牲质量；
- **场景不匹配**：面试季低频访问，GPU 实例空转仍计费，API 有调用才计费；
- **能力不匹配**：项目深挖追问、多文档综合、长上下文、语气控制、资料不足时拒绝编造——恰是核心诉求，小模型明显弱于托管大模型；
- **投入不可回收**：驱动 / CUDA / 推理框架维护与排障，在 1–2 月窗口后无法复用。

## C.3 实验环境的作品集价值（延后实施）

MVP 稳定后若有余力，可临时按量租 GPU 完成：小模型部署、量化对比、吞吐测试、LoRA 人格微调（L2）、与托管 API 的盲测对照，实验完成即释放实例。

> 即使未来落地 LoRA(L2)，系统结构仍为 **LoRA 人格模型 + RAG 事实知识库**：LoRA 负责表达习惯稳定性，**不负责记忆可变的简历与项目事实**，不得用 LoRA 替代 RAG。

> **总结论**：对招聘方使用的站点而言，**回答质量、稳定性、首字延迟**的优先级高于"模型是否自托管"、也高于"工程框架是否齐全"。有限精力应投入 RAG 检索质量、知识库清洗、人格构建、注入防护、答案引用、预约并发正确性、通知闭环与最小评测集。
