### 3. 功能需求（按功能域组织；每节含：行为描述 / 输入·输出 / 业务规则 / 异常流程 / 验收判定 + 源 R·UC）

### 4. 外部接口需求
- 4.1 用户接口（三页面布局、表单字段、颜色语义、二次确认页）
- 4.2 软件接口（DeepSeek API / SSE / SMTP / 飞书开放 API / 向量库 / 关系库）
- 4.3 通信接口（SSE 推送协议与版本号/序列号；Outbox 事件表）

### 5. 非功能需求（吸收 PRD §5 量化，逐项标注阈值与验收口径）
- 5.1 性能（首字≤3s / 普通 API≤500ms / 预约提交≤1.5s / SSE≤2s / 热更新分档 SLA / 通知邮件≤10s）
- 5.2 安全（AES-256 字段加密、Secret Manager、记住我令牌哈希、凭证不入前端/日志）
- 5.3 隐私（红格遮挡、飞书日常视图与后台应急只读视图明文边界、§8.7 七类数据分类）
- 5.4 可用性（上线前故障注入/健康检查/降级测试；上线后 SLO ≥99.5%）
- 5.5 备份与恢复（RPO≤24h / RTO≤4h / 月度演练）
- 5.6 限频防刷（§5 阈值表：注册/登录/预约/问答等）
- 5.7 兼容 / 视觉 / 会话 / 成本（仅桌面端；纯中文；会话跨登录保留；短期成本 ¥130–220）

### 6. 数据需求（指向领域模型 v1.1.2 为唯一规范源，不复制字段 Schema）

- 6.3 加密 / 留存 / 删除（引用 PRD §8.7 七类数据与补充规则）

### 7. 权限与角色（吸收 PRD §8.9 角色权限矩阵；区分「直接取消=不允许」与「锁定已约时段触发取消=允许且受审计」）

### 8. 异常与错误处理（吸收 PRD §8.12 错误码清单 + §4.6 通知失败矩阵）
