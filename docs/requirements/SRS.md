## 2. 总体描述

### 2.1 产品前景
面向招聘方/HR/面试官的对外个人站点：三大页面（简历问答页 / 项目展示页 / 动态面试表页）+ 数字分身（RAG 问答 + L1 人格层）+ 面试预约闭环（创建 / 修改 / 取消 / 二次确认 / 双通道提醒 / 候选人飞书视图 / admin 后台）。问答公开可问；预约、修改、取消需面试官登录。

### 2.2 用户特征与角色
| 角色 | 说明 | 账号域 |
|------|------|--------|
| 匿名访客 | 浏览三大页面、公开问答 | 无 |
| 面试官（interviewer） | 登录后预约/修改/取消/查看历史会话 | 独立于 admin |
| 候选人 admin（owner） | 知识库管理、不可约/公告管理、只读应急视图、去重例外、通知失败中心 | 独立于 interviewer |
| 系统任务 | 定时临近提醒、飞书同步、知识库索引 | — |

角色权限矩阵见 §7；账号隔离（面试官与 admin 同物理表、按 `role` 分认证域、邮箱全局唯一）见领域模型 §6.1。

### 2.3 运行环境约束
- **浏览器**：Chrome / Edge / Firefox 最新稳定版。
- **视口**：目标最低视口 **1280×720**；**平板横屏可用**；视口 **<1024px** 显示「建议使用桌面浏览器」阻断提示（不提供移动端页面，不做移动端竖屏适配）。**不得只写"仅桌面端"而漏掉"平板横屏可用"**（忠实吸收 PRD §4.1 / §5 已批准要求）。
- **部署**：云端部署（腾讯云，PRD §4 系统集成已确认），本机不搭服务；大模型推理经托管 LLM API。
- **时区**：中国标准时间（UTC+8）；时段以 `start_at`/`end_at` 时间戳存储。

### 2.4 设计与实现约束
- **RAG + L1 人格层**：MVP 仅用 DeepSeek 单模型（托管 API），混元 Fallback 为延后项。
- **硬规则（PRD §8.4#14）**：大模型仅负责 RAG 问答（含人格层 L1），**不得自动调用预约写入/修改/取消工具**；预约创建、改期、取消一律经确定性 UI（页面 3 表单 / 二次确认）与后端接口。
- **问答公开、预约需登录**：问答无需登录；页面 3 的预约/修改/取消需面试官登录（角色认证 + 记住我 14 天）。
- **账号隔离**：面试官账号体系与候选人 admin 账号体系分离。

### 2.5 MVP 边界与非目标（引用 `docs/baseline.yml`，不复制维护第二份清单）
- **MVP 硬规则**（引用 `baseline.yml` `mvp_hard_rules`，不重复罗列全文）：大模型只负责问答不自动写预约；密码登录（验证码仅注册验证/找回）；敏感字段逐列 AES-256、公司名 HMAC 指纹去重；并发抢占经 Slot 行锁 + 部分唯一索引不预占；通知通道独立重试不相互兜底；推荐问题异步生成缓存非实时；owner 取消经锁定已约时段触发原子取消、后台不提供直接删除预约入口。
- **延后项**：仅引用 `docs/baseline.yml` `deferred` 为唯一规范源；本 SRS 不复制维护该清单、不维护第二份状态源。
- **非目标（与 SRS 直接相关）**：不新增产品需求；不扩 MVP 范围；不提前做架构选型 / ADR / OpenAPI·SSE 契约 / 物理 Schema / 编码。

### 2.6 假设与依赖（PRD §8.2，统一标"外部依赖 / 待确认"，不阻塞设计，阻塞对应集成验收/上线）
- 邮箱与 SMTP 账号 / 授权码、域名 / 备案（备案需实名）。
- 飞书多维表格授权配置（候选人完整视图同步）。
- 人格素材（L1 自我介绍 / 风格样本）；项目 MD / 知识库文件。
- 面试季具体起止日期（影响云实例释放时点）。
- 以上为外部依赖，设计阶段可推进；相关项关闭前不得完成外部集成验收或发布上线。

## 3. 功能需求（按功能域组织）

> 每节含：行为描述 / 输入·输出 / 业务规则 / 异常流程 / 验收判定 + 源 R·UC。

### 3.1 站点三大页面（R1 / R3 / R6 / R15 / R25 → UC-01 / UC-02）
- **行为**：页面 1（简历问答页）左栏拆块简历 + 右栏问答窗口 + 推荐问题版块 + 文字可复制 + 左下角"下载简历 PDF"按钮 + "预约面试"入口；页面 2（项目展示页）HTML 动效项目卡片 + 右侧问答窗口 + 文字可复制 + 推荐问题 + 预约入口；页面 3（动态面试表页）见 §3.4。
- **输入·输出**：用户浏览/复制/下载；问答输入经 §3.2。
- **业务规则**：R1（三大页面）、R3（多页问答窗口公开可问）、R6（纯中文、简洁清爽、页面 2 动效、桌面端优先）、R15（简历 PDF 下载）、R25（页面 1/2 正文文字可复制）。
- **异常流程**：下载失败提示重试；问答失败见 §3.2/§8。
- **验收判定**：逐页核对左/右布局、推荐问题（缓存读取、缺失走兜底）、文字可复制、下载按钮、预约入口、纯中文桌面端（≥1280×720）正常（PRD §6）。

### 3.2 AI 问答与人格层（R2 / R3 / R4 / R7 / R22 / R23 / R24 → UC-03 / UC-04 / UC-05 / UC-15 / UC-16 / UC-17）
- **行为**：基于自有知识库（简历 / 项目 MD / PDF / DOCX / TXT）的 RAG 检索增强问答，叠加 L1 人格层（第一人称、本人风格/情商/逻辑）；越界以本人口吻拒答、不编造；流式输出；公开可问。
- **输入·输出**：用户输入问题（可粘贴复制文字）→ 检索知识库 → 人格层 L1 生成第一人称回答 → 流式返回；已登录用户会话持久化（§3.2 会话）。
- **业务规则**：
  - R2：知识库问答 + 越界护栏；MVP 单 DeepSeek。
  - R7：人格层 L1（persona 提示词 + few-shot），不编造事实。
  - R4：推荐问题 = 知识库索引完成后**异步生成并缓存**，页面读缓存、缺失走固定兜底；一键提问。
  - R22：知识库含项目 MD；R24：知识库热更新（增删改近实时重新索引）。
  - R23：登录用户问答会话跨登录保留（未登录不持久化）。
  - RAG 质量标准（PRD §4.2）：检索不到明确告知"资料未涵盖"不编造；多份冲突以最新/权威源为准；含指令性文本触发 Prompt Injection 防护不执行外部指令；删除后相关缓存答案失效；允许基于已知事实的合理推断但须标注"推测"；事实回答须基于知识库，人格层仅影响口吻。
  - 热更新边界（PRD §4.2）：单文件 ≤10MB、单次 ≤20 文件；支持文本型 PDF/OCR PDF/MD/DOCX/TXT；旧索引继续服务至新索引就绪；删除立即禁检索；相同文件去重。热更新 SLA 按文件类型分档（纯文本 P95≤60s / 扫描不可复制 PDF P95≤120s / OCR PDF 异步 P95≤5min / 删除 P95≤5s）。
- **异常流程**：
  - 越界 → UC-04 本人口吻拒答并引导（R2/R7）。
  - 模型服务不可用 → 返回"服务暂不可用"提示，**不调用第二模型、不生成无依据回答**（`MODEL_UNAVAILABLE`）。
  - 知识库索引失败 → 回滚旧索引继续服务（`INDEX_FAIL`）。
- **验收判定**：范围内命中率≥90%、越界拒答率≥95%、注入拦截率=100%、事实编造=零容忍（PRD §6 题库评测）；人格盲评通过率≥80%；会话跨登录可见。

### 3.3 面试官登录注册与会话（R9 / R19 / R20 → UC-06）
- **行为**：进入页面 3 须登录；无账号可注册（邮箱验证）；密码登录；支持"记住我"14 天免登录复访；密码找回（邮箱验证码）；防刷限频。
- **输入·输出**：邮箱/密码/验证码 → 建立认证会话（面试官网与 admin 隔离）。
- **业务规则**：R9（账号隔离）、R19（记住我 14 天）、R20（注册验证/找回/防刷）。**登录采用完整密码账号体系，验证码仅用于注册验证与密码找回，不用于登录**（PRD §8.4#13）。
- **异常流程**：凭证错误重试；无账号→注册发验证邮件（10 分钟有效）；忘记密码→邮箱验证码找回；限频→提示稍后（`AUTH_EXPIRED`/`EMAIL_UNVERIFIED`）。
- **验收判定**：注册（邮箱验证）/登录/记住我 14 天/找回/限频生效；面试官网与 admin 账号隔离（PRD §6）。

### 3.4 动态面试表页（R8 / R16 / R17 → UC-07 / UC-13）
- **行为**：登录后课程表式表格，绿=空闲/黄=选中待确认/红=已约或不可约；红格对其他面试官仅显"已预约"（无公司名）；页面顶部 owner 公告；SSE 实时刷新。
- **网格精确规则（PRD §4.5，忠实吸收）**：
  - 7 列（周一..周日）；行=30 分钟时段，9:30–22:00 共 25 行。
  - 展示窗口：本周+下周两个完整自然周（14 天），按完整自然周分页；"今天之前"置灰；仅允许预约"明天及以后"；最短提前量=面试日期前一自然日 **22:00（UTC+8）**。
  - 休息日：周末/法定节假日全天红；调休工作日可约（按普通工作日）；owner 人工覆盖优先于自动规则。
  - 用餐：每日 12:00–14:00、18:00–20:00 对应 4 格红。
  - 颜色语义：`available`(绿)/`booked`(红)/`owner_locked`(红)/`unavailable`(红，系统规则)；🟨黄格仅为前端 Session 临时态，**不落库、不预占、不参与并发判断**，刷新/超时即消失（PRD §4.5 黄格澄清）。
  - 选段：点绿格自动高亮该格+同列后续 2 格（共 1.5h=3 格）为黄；最晚可约起始 20:30；冲突（触及红格）持续悬浮"不可选当前时间段"。
- **业务规则**：R8（交互）、R16（红格隐私遮挡）、R17（owner 标红 + 顶部公告）。
- **异常流程**：SSE 不可用 → 轮询降级（UC-07 4a）。
- **验收判定**：绿/红/黄正确渲染；点绿自动占 1.5h；冲突持续悬浮；SSE≤2s 刷新；他人看不到红格明文；午/晚餐/周末/节假日固定红、调休可约；owner 可标红+编公告（PRD §6）。

### 3.5 预约创建（R10 / R12 / R16 / R26 → UC-08 / UC-09 / UC-19）
- **行为**：点绿格→高亮 1.5h→冲突校验→弹表单→"下一步"（不落库不预占）→转 UC-19 二次确认→确认后校验"一家公司一时段"→服务端原子锁写入→加密存储→3 格转红→SSE 刷新→双通道提醒+飞书同步+确认函投递。
- **输入·输出（表单字段）**：公司名称 / 会议平台 / 会议号 / HR 联系方式（电话 + **结构化双字段：姓氏 + 敬称下拉(先生/女士/老师)**）/ **备注（选填）**。提交信息加密存储、网站端不展示明文。
- **业务规则**：
  - R10（提交预约+加密+备注+结构化称呼）、R16（加密隐藏）、R26（二次确认+确认函）。
  - R12（一家公司一时段）：有效预约唯一约束 = 归一化公司名 与 账号取**并集拦截**（归一化=去空格/小写/去常见标点后缀；任一命中即拦截 `DUP_COMPANY`/`DUP_ACCOUNT`）；有效预约=`Appointment.status=active`；候选人可手工解除异常拦截（§3.7）。
  - R26 二次确认：确认页限时 **3 分钟**、**不预占时段**；收件邮箱固定为注册已验证邮箱、**只读不可编辑**（`EMAIL_NOT_EDITABLE`）；公司名/称呼可返回修改；确认提交走原子锁，被抢占返回 `SLOT_TAKEN`。
- **异常流程**：冲突持续悬浮；超时 `CONFIRM_EXPIRED`（作废无持久化）；并发 `SLOT_TAKEN`（另一人绿转红）；公司/账号重复 `DUP_COMPANY`/`DUP_ACCOUNT`（UC-09）；试图改邮箱 `EMAIL_NOT_EDITABLE`。
- **验收判定**：绿转红+加密+3 分钟超时作废无脏数据+确认期被抢占返回 `SLOT_TAKEN`+收件邮箱只读+双通道提醒+确认函投递（PRD §6 / UC-19）。

### 3.6 预约修改 / 取消（R11 / R26 → UC-10 / UC-19）
- **行为**：仅归属人可改自己红格或取消。
  - **改会议号 = 原地改字段**（不涉及时段占用）。
  - **改时间 = 原子事务**：同一事务内锁新段→占新段→释旧段→提交；新段不可用则原预约保持不变（**禁止先释放原格再重选**）；成功后发双通道通知+飞书同步+**改期重发确认函（标注时间已更新）**。
  - **取消 = 事务中释放原 3 格**+触发通知+飞书同步+**取消成功发取消告知函（必须）**。
- **业务规则**：R11（修改/取消原子）、R26（改期/会议号变更重发更新函、取消发告知函）。
- **异常流程**：改时间新格被占 → 提示重选、原预约不变（`SLOT_TAKEN`，UC-10 2a）；权限不足 `PERM_DENIED`。
- **验收判定**：会议号原地改、原子改期无数据丢失（≥50 并发重复≥10 次仅一人成功）、本人可改/取消、其他面试官看不到红格明文（PRD §6）。

### 3.7 owner 强制取消与去重例外（R14b / R12 → UC-20 / UC-22）
- **行为（owner 强制取消，R14b）**：admin 在后台**锁定已预约时段**（输入取消原因）触发系统**原子取消**：释放占用 3 格（变 `owner_locked`）、向该面试官注册邮箱发取消告知函（主题「（已取消）」）、写 AuditLog。**后台不提供直接修改/删除预约入口**（与权限矩阵一致）。
- **业务规则**：R14b；不称"三通道通知面试官"；`owner_locked` 红格优先级高于自动规则；解除锁定恢复绿（不恢复已取消预约）。
- **去重例外（R12，UC-22）**：集团不同事业部被归一化指纹误判时，admin 创建**一次性例外授权**（`CompanyBookingException`），仅绕过公司指纹唯一约束（绝不绕过 `uq_active_user` 一人一时段）；未消费可撤销、消费后一次性失效、已消费撤销不影响已建预约；全程入 AuditLog。
- **异常流程**：告知函投递失败 `CONFIRM_MAIL_FAIL`（不回滚释放、可手动重发）；重复操作幂等。
- **验收判定**：owner 锁定→3 格 `owner_locked`+SSE 刷新红+告知函+审计；去重例外一次性放行且 `uq_active_user` 不绕过。

### 3.8 候选人侧视图与提醒（R13 / R14 / R14a / R18 / R21 → UC-11 / UC-12 / UC-14 / UC-23）
- **飞书完整视图（R14，UC-11）**：系统 DB 为唯一真相源，预约变更实时/近实时同步至飞书多维表格（全公司明文：公司/平台/会议号/HR联系方式/备注/时段/状态）；同步失败邮件告警候选人+飞书任务重试（R21/UC-11 3a）。
- **双通道提醒（R13，UC-12，MVP）**：新预约/修改(改时间)/取消事件实时推送候选人**飞书+邮箱**；面试前 **10 分钟**临近提醒（R18/UC-14）；微信助理为延后项。
- **后台只读应急视图（R14a，UC-23）**：飞书不可用时，admin 在网站后台**只读**查看完整预约（全公司明文）、通知投递状态、飞书同步状态/故障记录；**不可改/删预约**。
- **通知可靠性语义（PRD §4.6，见 §4.3）**：业务事务 + 可靠持久化的业务事件（Outbox 模式）+ 异步消费者；每事件唯一幂等 ID；≤3 次指数退避重试；不重复产生业务后果；预约成功不依赖第三方通知成功。
- **失败矩阵（PRD §4.6）**：飞书失败邮箱成功→重试飞书；邮箱失败飞书成功→重试邮件+飞书告警；均失败→后台高优先级告警持续重试（二者不互为兜底）；飞书同步失败→邮件告警+飞书任务重试；确认函失败→不回滚预约+告警+可手动重发。
- **验收判定**：双通道幂等不重复、单通道失败不影响其余、失败独立重试+告警（PRD §6）；飞书视图日常可见、同步失败告警；应急视图只读。

### 3.9 管理后台（R5 / R22 / R24 → UC-13 / UC-16 / UC-17 / UC-18 / UC-21 / UC-22）
- **行为**：admin 后台登录（账号密码，独立于面试官）→ 知识库上传/删除/热更新（R5/R22/R24，UC-16/UC-17）→ 对话记录查看（UC-18）→ 不可约时段管理（UC-13）→ 公告管理（UC-13）→ 去重例外管理（UC-22）→ 通知/同步失败中心手动重发（UC-21）→ 确认函手动重发（R26）→ 候选人联系信息配置（R26 手机号）→ 审计日志查看。
- **业务规则**：R5（后台能力）、R22（项目 MD）、R24（热更新分档 SLA）、R26（确认函手动重发+手机号配置）；admin 对预约为**只读应急**，仅"锁定已约时段触发取消"这一受审计特殊操作可发起候选人侧取消（§7/PRD §8.9）。
- **异常流程**：解析失败提示；热更新索引失败回滚旧索引（`INDEX_FAIL`）。
- **验收判定**：admin 可登录、传知识库(热更新)、看对话、只读查看完整预约、标不可约、编公告、去重例外、失败中心重发（PRD §6）。

## 4. 外部接口需求

### 4.1 用户接口（UI 行为）
- 三页面布局：页面 1 左简历/右问答/推荐问题/下载按钮/预约入口；页面 2 动效项目/右问答；页面 3 课程表（需登录）。
- 表单字段与二次确认表（§3.5）：公司名/平台/会议号/HR 联系方式(姓氏+敬称)/备注；确认表核对公司名/收件邮箱(只读)/称呼三要素。
- 颜色语义与二次确认页显著提示（§3.4/§3.5）。
- 语言：纯中文界面（R6）。

### 4.2 软件接口（行为契约，不含 URL/Schema）
- **模型推理（DeepSeek 托管 API）**：用于 RAG 生成 + 人格层 L1；不可用时应降级返回 `MODEL_UNAVAILABLE`，**不切换第二模型、不编造**（PRD §4.2 / §8.12）。
- **向量库 / 关系库**：知识库切片与向量（检索增强）；账号/会话/预约/时段/不可约/公告等关系数据（领域模型 §6）。
- **邮件推送（SMTP）**：注册验证 + 候选人双通道提醒 + 飞书同步失败告警 + 预约确认函/取消告知函（§3.5/§3.6/§3.8）。凭证存 Secret Manager，不进前端/日志。
- **飞书开放 API**：候选人完整视图同步（§3.8）+ 提醒；授权配置为外部依赖（§2.6）。
- **实时推送（SSE）**：见 §4.3。
- **注意**：具体 REST 路由、请求/响应字段、SSE 事件载荷、飞书/邮件 SDK 细节**不在本文定义**，由《接口契约》与架构 ADR 规定。

### 4.3 通信 / 通知接口行为（不定义物理表，不设计 SSE payload）
- **SSE 推送行为（PRD §4.5 实时刷新，忠实吸收）**：
  - 事件带**版本号 / 序列号**，接收端按序应用；
  - 断线后接收端**重新拉取全量快照**恢复；丢失事件经全量刷新恢复；
  - 多实例部署时，事件传播必须保证一致性与有序恢复（具体机制如 Redis Pub/Sub / 中心化通道由架构 ADR 决定，本文不预定义实现）；
  - 推送内容 ≤2s 到达客户端。
  - **不在此设计 SSE 事件载荷字段/URL**（留给接口契约）。
- **通知可靠性行为（PRD §4.6，引用领域模型 NotificationEvent/NotificationDelivery）**：
  - 业务事件写入 Outbox（`NotificationEvent`，带唯一幂等键 `idempotency_key`）；异步消费者投递，每通道每次尝试记 `NotificationDelivery`；
  - 通道独立重试（≤3 次、指数退避），**不相互兜底**；失败通道独立告警；
  - 手动重发 = 新建 `NotificationDelivery` 尝试记录（`attempt_no`+1，幂等键含新 `event_version`）；
  - **预约成功不依赖第三方通知成功**（确认函失败 `CONFIRM_MAIL_FAIL` 不回滚预约）；
  - 临近提醒：定时任务扫描 `reminder_due` 事件；改期/取消时旧提醒置 `cancelled`、不重复不漏发。
  - **不在此定义 Outbox/NotificationDelivery 物理表结构**（见领域模型 §5/§6.11–§6.12）；本文仅规定其**可靠性行为契约**。

## 5. 非功能需求（吸收 PRD §5 量化，逐项标注阈值与验收口径）

### 5.1 性能（量化，P0-6）
- 问答首字响应：模型正常、并发≤20 时 P95 ≤ 3s（流式首字）。
- 普通页面/API：P95 ≤ 500ms。
- 预约提交（写库+加密+事务+Outbox 事件写入）：P95 ≤ 1.5s（不含异步通知）。
- SSE 状态传播：服务端提交后 ≤ 2s 到达客户端。
- 知识库热更新：按「热更新分档 SLA」执行（纯文本 P95≤60s / 扫描不可复制 PDF P95≤120s / OCR PDF 异步 P95≤5min / 删除 P95≤5s）。
- 选段/冲突校验前端即时（<100ms）。
- 通知消费：邮件 P95 ≤ 10s 提交至 SMTP（异步，不计入预约事务）。

### 5.2 安全
- 面试官/候选 admin 鉴权；敏感字段 AES-256 加密存储、网站端不解密（本人/飞书/后台应急视图除外）；SMTP/飞书凭证存 Secret Manager 不进前端/日志；记住我令牌哈希+失效机制（PRD §5 / §8.7）。

### 5.3 隐私
- 红格对他人不可见任何可识别信息（仅"已预约"）；完整数据仅经飞书日常视图与后台只读应急视图可见；站点提供隐私说明（§8.6）；敏感操作入审计日志并脱敏（PRD §5 / §8.7）。

### 5.4 可用性
- 上线前：故障注入/健康检查/自动重启/降级（SSE 断线→重拉快照；飞书/邮件失败→失败通道独立重试告警，不切换其他通道）测试通过。
- 上线后 SLO：月度可用性 ≥ 99.5%（自然月持续度量）。

### 5.5 备份与恢复
- 数据库每日自动备份（加密）；RPO ≤ 24h，RTO ≤ 4h；至少每月一次恢复演练（PRD §5）。

### 5.6 限频防刷（阈值已确认，上线后按监控调整）
- 注册（同邮箱 60s/1 次、每邮箱每小时≤3、同 IP 每小时≤5）；邮箱验证码（10 分钟有效、错误≤5）；登录（同账号 15 分钟失败 5 次锁 15 分钟、同 IP 每分钟≤10）；预约提交（同账号每小时≤10）；问答 API（同账号每分钟≤20、同 IP 每分钟≤30）；单次对话上下文≤20 轮；SSE 连接（同账号≤2 并发）（PRD §5 阈值表）。

### 5.7 兼容 / 视觉 / 会话 / 成本（PRD 已确认约束，不展开实现）
- 兼容：**桌面端 Chrome/Edge/Firefox 最新稳定版；最低视口 1280×720；平板横屏可用；<1024px 阻断提示；不做移动端竖屏适配**（忠实吸收，不漏"平板横屏可用"）。
- 视觉/终端：纯中文、简洁清爽；页面 2 动效互动；仅桌面端。
- 会话：登录用户问答会话跨登录保留（R23），未登录不持久化。
- 成本：**腾讯云部署（PRD §4 系统集成已确认）**；短期（面试期 1–2 月）含域名 ≈ ¥180–220、不含域名 ≈ ¥130–170（PRD §5 非功能需求·成本估算）。**SRS 仅记录上述已确认约束，不展开服务器规格、网络拓扑、Redis、部署方案——留待架构/ADR。**

- 日志脱敏：会议号/电话等写入前脱敏；敏感操作入审计。

## 8. 异常与错误处理（吸收 PRD §8.12 错误码清单）

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `SLOT_TAKEN` | 时段已被抢占 | 提示重选，网格刷新为红 |
| `DUP_COMPANY` | 同公司已有有效预约 | 拦截+提醒「一家公司仅可约一个时段」 |

| `EMAIL_UNVERIFIED` | 邮箱未验证 | 引导验证 |
| `AUTH_EXPIRED` | 登录过期 | 重新登录 |
| `PERM_DENIED` | 修改权限不足（非归属人） | 拒绝 |
| `FEISHU_SYNC_FAIL` | 飞书同步失败 | 邮件告警候选人 + 飞书任务重试 |
| `NOTIFY_PARTIAL` | 通知部分失败 | 失败通道重试，其余成功 |
