> 本文档是《个人 AI 问答网站需求文档（v2.3.3）》的配套工件，属软件工程"需求/分析"阶段产物。
> 本规约评审通过后可进入 SRS、UI 与架构设计。PRD §8.2 中的外部资源待确认项不阻塞设计，但相关项关闭前，不得完成外部集成验收或发布上线。编码准入仍以 `docs/baseline.yml` 的 `development_gate` 为准。
> v1.7.2 相对 v1.7.1 的变化（需求文档 v2.3.3 第六轮评审最终一致性整改）：新增 UC-23 后台只读应急视图（R14a 追溯改 UC-23，不再复用飞书用例 UC-11）；UC-20 owner 强制取消后置条件修正为「三格变 `owner_locked`（红色不可约），SSE 刷新为红色不可约」；UC-21 手动重发「新 DeliveryAttempt」→ 新的 `NotificationDelivery` 尝试记录（`attempt_no`+1）；配套领域模型 v1.1.2、PRD v2.3.3。

> v1.7.1 相对 v1.7 的变化（需求文档 v2.3.2 第五轮评审一致性整改）：删除「编码准入检查表」（改引用 `docs/baseline.yml` 唯一规范源）；UC-20 owner 强制取消统一为「锁定已预约时段触发原子取消」（与权限矩阵一致，后台不提供直接删除预约入口）；UC-22 公司去重例外改为「一次性授权 `CompanyBookingException`，被 `DUP_COMPANY` 拦截时尚未生成 Appointment 行」，且 `uq_active_user` 始终生效；R14b 重编号——R14a 后台只读应急视图 / R14b owner 强制取消，补 R14a 追溯；配套领域模型 v1.1.1。
> v1.7 相对 v1.6 的变化（需求文档 v2.3.1 第四轮评审整改同步）：修正 UC-10 改期描述与基本流统一为原子流程（锁新段→占新→释旧，不先释放）；双通道后置"三端"→"已启用通道（飞书+邮箱）分别记录成功/失败"；UC-16 热更新 SLA 改引需求分档 SLA（≤60s/≤120s/异步≤5min）；UC-19 确认函补齐会议平台/会议号/起止时间字段与脱敏规则；外部系统表"同步兜底"→"飞书同步失败告警"；新增 UC-20（owner 强制取消，R14b）/ UC-21（通知失败中心）/ UC-22（公司去重例外解除）并补 R14b 追溯。
> v1.6 相对 v1.5 的变化（需求文档 v2.3 开发准入收口版同步）：重写预约/时段/邮件三独立状态机（Slot/Appointment/MailDelivery，手动重发=新DeliveryAttempt）；确认函模板补会议平台/会议号变量、取消告知由可选→必须；统一存储策略（敏感字段逐列 ciphertext、公司名 fingerprint 去重、start_at/end_at 明文受访问控制、active 预约按 fingerprint+user_id 部分唯一索引）；删除笼统"邮件兜底"、明确通知失败矩阵；拆预约事务(≤1.5s)与异步通知(邮件≤10s SMTP)性能口径；展示窗口改两完整自然周；管理后台补5项能力；owner 间接取消权限表述；NotificationDelivery 扩字段；candidate_phone 改 ciphertext；追踪矩阵标注移测试计划；表单提示去施压、场景18补会议号、微信配置移延后、价格迁 ADR。
> v1.5 相对 v1.4 的变化（需求文档 v2.2 一致性收口同步）：统一 MVP 状态——**MVP=DeepSeek 单模型（混元 Fallback 延后）、MVP=邮箱+飞书双通道（微信助理延后）、推荐问题=异步生成缓存（非实时）；改期改为原子事务（禁"先释放原格"）；公司名"精准匹配"→"归一化比较+账号并集"；候选人视图"仅在飞书"→飞书日常+后台应急；通知体系拆分为候选人（双通道）与面试官（注册邮箱）；状态机移除持久化 draft_confirming/pending；敏感字段全入 encrypted_payload、remember_token 改存哈希**。
> v1.4 相对 v1.3 的变化：新增 **UC-19 预约信息二次确认与确认函回执（R26）**；UC-08 改为两步提交（填表 → 二次确认 → 原子落库），称呼字段改为结构化「姓氏 + 敬称」；新增业务场景 **S18**；补充追溯关系 R26 ↔ UC-08/UC-19。
> v1.3 相对 v1.2 的变化：页面1/2 文字可复制；预约表单加「备注」；新增**会话历史持久化（UC-17，像豆包）**；新增**知识库热更新（UC-18，增删改近实时生效）**；推荐问题=异步生成缓存（非实时）；微信通道=WorkBuddy 微信助理（延后项）；记住我=14 天；公司名=归一化比较+账号并集；人格=L1；临近提醒=10 分钟；补充限频建议值引用。

## 1. 参与者（Actors）

| 参与者 | 类型 | 说明 |
|--------|------|------|
| 面试官 / 招聘方 | 主参与者（外部） | 浏览站点、问答（公开，登录后会话持久化）、登录后预约 / 修改 / 取消 |
| 候选人 / 站长（本人） | 主参与者（内部） | 即用户；飞书看完整表（飞书不可用时经 admin 后台只读应急视图）、收双通道提醒（飞书+邮箱；微信延后）；admin 后台管理（知识库热更新/不可约/公告） |
| 大模型问答引擎 | 系统参与者 | RAG + 人格层（L1）作答 |
| 预约服务 | 系统参与者 | 预约写入、校验、并发锁、实时推送 |
| 邮件推送 | 外部系统 | 注册验证 + 候选人提醒 + 飞书同步失败告警 |
| 微信推送（WorkBuddy 微信助理，延后项） | 外部系统 | 候选人微信提醒（MVP 不在范围内） |
| 飞书多维表格 / 飞书机器人 | 外部系统 | 候选人完整视图同步 + 提醒 |

```
面试官 ── S1 浏览首页 ── S3 问答 ──(越界)──> S4 拒答

   ├── S5 推荐问题(异步缓存) ──> S3

   │     └── S10 修改/取消本人预约(会议号原地/时间换格)
```
