# TASK-KB-EVAL-002 判别式评测集（哈希 vs BGE-M3 语义对比）

> **状态**：**Closed（用户 2026-08-15 显式授权关闭）**——判别式评测集已实现并验证（纯向量层哈希 1.8 vs BGE-M3 1.3，verified_commit=118a02d）。
> **依赖**：TASK-KB-EMB-001 已验证（BGE-M3 接入，HIT=8/8 与哈希持平——字面用例测不出语义差异，本任务解决此问题）

## 1. 背景（为什么需要判别式用例）
EVAL-001 的 8 条命中用例都是**字面关键词命中**（问句直接含文档词），哈希与 BGE-M3 都 8/8——
**测不出语义差异**。语义向量的真实价值要靠**判别式用例**量化：
问句用同义词/异表述（字面与文档零重叠、语义相同）→ 哈希（字符哈希，无语义）必挂，BGE-M3（语义向量）应命中。

## 2. 目标
1. **扩语料** 4→10 篇（增加 top-k 区分度，削弱"候选覆盖全"效应）
2. **新增语义改写型用例**（6-8 条，判别式核心）：
   - 「你在哪所学校读的书？」→ 文档只有「[学校已脱敏]」（字面零重叠，语义同）
   - 「你拿过哪些奖？」→ 文档只有「国家奖学金 / 挑战杯」（字面零重叠）
   - 「Litchi 这个平台的架构怎么设计的？」→ 文档有「Planner→Guard→Executor→Synthesizer」
   - 「睡眠项目里怎么保证长任务不卡死？」→ 文档有「Temporal 长任务编排/失败重试」
3. **扩拒答型** 6→10 条（更多越界/无依据场景）
4. **输出对比数字**：同一评测集跑两遍（哈希 embedding vs BGE-M3 embedding）→
   「哈希 x% vs BGE-M3 y%」的判别式对比 = 简历最硬检索质量证据

## 3. 范围（严格限定）

## 4. 技术要点（含实测认知修正）
- 语料仍是测试内嵌中文 md（10 篇：模拟简历/两项目 + 教育/技能/实习/认证/RAG/Agent 笔记），**不含用户真实个人信息**
- **认知修正（2026-08-15 实测）**：CJK 单字 BM25 + 10 篇小语料 → 混合链路 top-6 几乎全召回，向量差异被 BM25 兜底稀释（EXTREME 组哈希 avg-rank 仍 2.2 与 SEMANTIC 持平）——**这证明混合检索对 embedding 质量退化鲁棒（优点）**；要量化语义向量真实价值必须**绕过 BM25 直测纯向量层**（`test_pure_vector_ranking`，`repository.search_chunks` 直查）
- 对比方法：`JIANLI_LLM_EMBEDDING_*` 有则 BGE-M3、无则哈希（`_settings` 从 `Settings.from_env()` 透传 embedding 配置——EVAL-002 曾漏读导致两遍同用哈希，`9376767` 修复）→ 用户跑两遍拿对比
- 拒答型仍 xfail（P1 阈值缺陷基线不变，本任务不修检索行为）
